# Product Metrics

Плагин для ведения каталога и системы продуктовых метрик вместе с AI-агентом. Установите один пакет, создайте каталог в своей рабочей папке и описывайте метрики разных продуктов обычными запросами.

**Пример:** «Зафиксируй конверсию в оплату по этому документу. Проверь, нет ли похожего определения, сохрани неизвестные правила как вопросы и обнови реестр».

## Что внутри

Шесть навыков используют общий формат карточек и подходят для разных задач.

| Навык | Когда нужен |
|---|---|
| `metrics-setup` | Создать каталог в новой или существующей базе знаний |
| `metric-catalog` | Найти, объяснить, создать или изменить определение метрики |
| `metrics-system` | Собрать систему метрик под цель; режимы: карта или дерево, метрики A/B-теста, OKR из дерева |
| `metrics-review` | Проверить каталог, отчёт или дашборд; отдельно - не vanity ли метрика |
| `diagnose-metric` | Объяснить, почему метрика изменилась, и выдать диагностическую записку |
| `metrics-memo` | Подготовить записку к недельному триажу, месячному или квартальному обзору по ряду значений |

## Примеры запросов

После установки плагина можно писать агенту обычным языком. Выберите пример, замените детали на свои и приложите упомянутые документы, SQL или данные. Это вымышленные ситуации, а не готовые данные для расчёта.

Начать можно без каталога: сначала агент ответит на вопрос, затем предложит сохранить результат. Для настройки и наполнения каталога используйте первый пример.

### Собрать каталог метрик

```text
У нас описания метрик разбросаны по папке docs/analytics.
Помоги собрать единый каталог для продукта: настрой его
и перенеси существующие определения. Сохрани их смысл,
а противоречия и вопросы вынеси отдельно.
```

**Навыки:** `metrics-setup` и `metric-catalog`. **Результат:** каталог с карточками метрик, реестром и списком нерешённых вопросов.

### Разобраться с определением

```text
Вот описание конверсии в оплату и SQL, которым мы её считаем.
Объясни простыми словами, кто попадает в расчёт,
какой период используется и совпадает ли запрос с определением.
```

**Навык:** `metric-catalog`. **Результат:** объяснение расчёта, найденные расхождения и вопросы. Чтение SQL само по себе не подтверждает правильность данных.

### Выбрать метрики под задачу

```text
Хотим сократить время оформления заказа.
Помоги выбрать основной показатель и связать его с тем,
на что команда может повлиять. Добавь показатели,
по которым заметим, если ускорение ухудшит результат.
```

**Навык:** `metrics-system`, режим `map`. **Результат:** карта или дерево метрик с основной метрикой и защитными показателями. Предположения о влиянии отделены от подтверждённых связей.

### Подготовить A/B-тест

```text
Тестируем новую регистрацию.
Предложи, какими метриками оценить успех,
за какими возможными ухудшениями следить
и какие пороги нужно согласовать до запуска.
```

**Навык:** `metrics-system`, режим `experiment`. **Результат:** метрики успеха, защитные и диагностические показатели, а также пороги для согласования до запуска.

### Сформулировать OKR

```text
Вот наше дерево метрик.
Помоги сформулировать цель и ключевые результаты на квартал.
Для каждого укажи исходное значение, целевое, срок и владельца.
Если чего-то не хватает — оставь вопрос.
```

**Навык:** `metrics-system`, режим `okr`. **Результат:** проект цели и ключевых результатов, связанных с деревом метрик. Неизвестные значения и владельцы обозначены явно; предложенные цели требуют согласования.

### Разобраться с падением показателя

```text
Средний чек снизился.
Вот данные по неделям и категориям товаров.
Проверь, насколько необычно изменение,
какие категории дали основной вклад и что нужно проверить,
чтобы выяснить причину.
```

**Навык:** `diagnose-metric`. **Результат:** разбор изменения и план проверок. Вклад категории не выдаётся за доказанную причину; если данных недостаточно, агент укажет, чего не хватает.

### Подготовиться к встрече

```text
Вот значения метрик по неделям за последние три месяца.
Собери короткую сводку к еженедельному обсуждению:
что требует внимания, какие вопросы задать
и что проверить первым.
```

**Навык:** `metrics-memo`. **Результат:** сводка со значениями метрик, оценкой отклонений, вопросами и известными владельцами. Если владельцы не указаны, агент обозначит пробел.

### Проверить дашборд

```text
Вот наш дашборд и описание решений, которые мы по нему принимаем.
Посмотри, чего не хватает, что дублируется
и какие показатели выглядят полезными,
но мало помогают выбрать действие.
```

**Навык:** `metrics-review`, режим `dashboard`. **Результат:** замечания и предложения по дашборду с объяснением, на какие решения они влияют.

Если каталог есть, агент читает карточки и сохраняет записки в `metrics/memos/`. Карту системы можно нарисовать скриптом `plugins/product-metrics/scripts/render_system.py`: он проверяет `METRICS_SYSTEM.md` и строит схему Mermaid. Учебные продукты для проб: `beacon`, `atlas`, `shop`, `platform`.

Плагин хранит общие правила. Ваш каталог хранит знания организации: продукты, определения и ссылки на источники. Обновление плагина не должно менять ваши карточки или методику расчёта.

## Установка в Codex

Добавьте источник плагинов и установите пакет из терминала с установленным Codex CLI.

```bash
codex plugin marketplace add Working-in-IT/product-metrics --ref v0.3.0
codex plugin add product-metrics@working-in-it-metrics
```

Затем откройте новую сессию в своей рабочей папке. Если версия клиента не поддерживает `plugin add`, после добавления источника откройте каталог плагинов в приложении, выберите **Working in IT · Product Metrics** и установите **Product Metrics**. Возможности команд зависят от версии клиента; справка - `codex plugin --help`. [Документация установки](https://developers.openai.com/plugins/build/plugins).

## Установка в Claude Code

Выполните две команды в терминале с установленным Claude Code.

```bash
claude plugin marketplace add https://github.com/Working-in-IT/product-metrics.git
claude plugin install product-metrics@working-in-it-metrics
```

В новой сессии навыки вызываются, например, как `/product-metrics:metrics-setup` или выбираются агентом по запросу. [Документация плагинов](https://code.claude.com/docs/en/plugin-marketplaces).

## Первый запуск

Откройте собственный проект и попросите агента подготовить место для определений.

```text
Используй metrics-setup из Product Metrics.
Создай каталог для продуктов Billing и Mobile в папке metrics/.
Существующие описания лежат в docs/analytics/.
```

Агент создаст `CATALOG.md` с местными путями, `INDEX.md` для поиска и журнал изменений. Если эти файлы уже существуют, он сначала прочитает их и предложит минимальное дополнение. Пользовательские файлы создаются в вашем проекте, вне установленного плагина.

После этого можно обращаться с такими задачами:

- «Опиши месячную активную аудиторию Mobile по приложенному определению».
- «Чем отличаются эти два показателя активации?»
- «Собери систему метрик для сокращения времени оформления заказа».
- «Проверь каталог на противоречия и неподтверждённые правила».

В последующих сессиях агент читает профиль, реестр и нужные карточки. Если каталогов несколько, укажите нужный `CATALOG.md` в запросе или в инструкциях своего проекта.

## Как устроено хранение

Карточка - Markdown-файл с YAML-шапкой, то есть структурированными полями в начале. Она хранит смысл, формулу, выборку, временное окно, источник, владельца и версию определения. Блок «Как посчитать» содержит SQL (запрос к данным) или другой способ расчёта: полный код либо ссылку на файл, движок, зависимости, параметры, результат и свидетельства проверки.

**Реестр** помогает найти карточку. **Система метрик** связывает карточки с целью и различает формулу, защитное условие и причинную гипотезу. **Защитная метрика** помогает заметить, когда улучшение основного показателя сопровождается ухудшением результата. Согласованное определение и проверенный расчёт имеют отдельные статусы.

Посмотрите [формат](plugins/product-metrics/shared/references/FORMAT.md), [шаблон карточки](plugins/product-metrics/shared/templates/metric.md) и [учебный каталог](plugins/product-metrics/shared/examples/INDEX.md). Все примеры вымышленные; данные для реальных расчётов пользователь предоставляет отдельно.

## Как добавить SQL к метрике

Передайте агенту карточку и исходный запрос. Он сохранит условия воспроизведения и отделит текущую реализацию от предложенного исправления.

```text
Используй Product Metrics / metric-catalog.
Дополни карточку [метрика] расчётом из [файл SQL].
Укажи движок, таблицы, параметры периода, форму результата
и что уже проверено. Сохрани полный запрос или ссылку на него.
Неизвестные зависимости обозначь как пробелы.
```

Правила находятся в [описании расчёта](plugins/product-metrics/shared/references/CALCULATION.md). Два [учебных SQL-примера](plugins/product-metrics/shared/examples/sql/README.md) вычисляют долю успеха и среднее время. Их можно запустить на вымышленных строках без подключения к базе организации:

```bash
python3 plugins/product-metrics/shared/examples/sql/run_examples.py
```

Код примеров написан для SQLite. Для своего продукта нужны его реальные таблицы, диалект и правила подготовки данных. Успешный учебный тест не означает, что реальная метрика проверена. Существующие карточки дополняются постепенно; `schema_version: 1` сохраняется.

## Обновления и совместная работа

Храните каталог команды в её собственной базе знаний или закрытом репозитории. Все участники используют этот каталог и согласованную версию плагина. Настройка командных путей находится в `CATALOG.md`; менять исходники плагина для этого не требуется.

Codex в примере закреплён на теге `v0.3.0`. Для перехода на следующий выпуск обновите выбранный Git ref источника и установку по инструкции своего клиента. Для Claude Code источник по умолчанию следует основной ветке; порядок обновления - [в инструкции передачи](plugins/product-metrics/shared/SHARING.md). Изменение версии формата карточек потребует отдельной явной миграции.

## Проверка и ограничения

Плагин предназначен для работы с определениями и описаниями расчётов в файлах. В комплект входят [контрольные сценарии](plugins/product-metrics/shared/CHECKS.md) и [проверка упаковки](scripts/validate_package.py). Проверка документов и учебных запросов не доказывает корректность данных организации.

Установка проверена на Codex CLI 0.143.0 и Claude Code 2.1.283; [результаты и ограничения](VALIDATION.md) доступны отдельно.

Для разработчика пакета:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python scripts/validate_package.py
claude plugin validate . --strict
```

Зависимости нужны только для проверки выпуска; навыки работают как инструкции и шаблоны; для локальных SQL-примеров достаточно стандартной библиотеки Python. Он не содержит подключения к базе данных, фоновой службы или механизма отправки каталога автору. Файлы, которые читает агент, обрабатываются в среде выбранного пользователем агента.

## Источники и участие

Формат создан по результатам обзора открытых практик; [источники](plugins/product-metrics/shared/references/SOURCES.md) доступны отдельно. Это самостоятельная методика, не официальный отраслевой стандарт.

Ошибки и предложения можно оставлять в Issues, изменения - предлагать через pull request. Для примеров используйте вымышленные данные. Условия повторного использования - [MIT](LICENSE); история выпусков - [CHANGELOG.md](CHANGELOG.md).
