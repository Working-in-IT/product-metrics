# SQL-примеры: доля успеха и время сценария

Два полных запроса показывают последний шаг расчёта метрик Beacon из подготовленной таблицы сценариев. Они выполняются в SQLite — локальной базе данных, включённой в стандартную библиотеку Python. Все строки вымышленные; подключения к данным организации нет.

## Входы и граница примера

Запросы реализуют агрегацию версии 1 определений [доли успеха](../products/beacon/metrics/success_rate.md) и [среднего времени](../products/beacon/metrics/successful_scenario_time_mean.md). Версия учебного кода — 1; файлы фиксируются тегом выпуска плагина `v0.2.0`.

Вход `scenario_facts` — одна строка на пару `product_id, scenario_id`. Поля: `started_at` — момент начала; `outcome` — `success`, `failed`, `cancelled` или `timeout`; `duration_seconds` — целое число секунд до успеха от 0 до 86 400 включительно, иначе `NULL`. Время хранится одинаковыми строками `YYYY-MM-DDTHH:MM:SSZ`, по UTC (всемирному координированному времени). Одинаковый формат нужен для сравнения границ.

**До этих запросов** источник обязан удалить дубли событий, выбрать первое валидное начало и первый терминальный исход, исключить некорректные, тестовые и автоматические сценарии по [правилам данных](../DATA_CONTRACT.md). Нужен снимок всех поступивших к `as_of` событий. Этот этап здесь не реализован и не проверен: [fixture.sql](fixture.sql) создаёт уже подготовленные учебные строки. Запросы не являются полной цепочкой расчёта из сырых событий.

## Код и параметры

Канонические запросы — [success_rate.sql](success_rate.sql) и [successful_scenario_time_mean.sql](successful_scenario_time_mean.sql). Параметры `:name` передаются через `sqlite3.execute(sql, params)`; это не подстановка текста в SQL.

| Параметр | Тип и пример | Значение |
|---|---|---|
| `product_id` | текст, `beacon` | Продукт |
| `period_start` | текст UTC, `2026-08-01T00:00:00Z` | Начало календарного месяца включительно |
| `period_end` | текст UTC, `2026-09-01T00:00:00Z` | Начало следующего месяца, не включается |
| `as_of` | текст UTC, `2026-09-04T00:00:00Z` | Дата получения снимка данных |

Передавать нужно валидные даты в указанном формате и границы полного месяца; произвольное окно меняет определение. Месячная группа готова по времени через 24 часа на исход и ещё 48 часов на доставку после `period_end`. До этого запросы возвращают `preliminary` и `NULL` вместо значения; счётчики остаются предварительными. Истечение времени не доказывает полноту источника.

## Запуск и ожидаемый результат

Из корня репозитория выполните команду; из установленного плагина используйте путь к тому же файлу в `shared/examples/sql/`.

```bash
python3 plugins/product-metrics/shared/examples/sql/run_examples.py
```

[Проверяющий скрипт](run_examples.py) создаёт базу в памяти, выполняет оба SQL-файла с именованными параметрами и сверяет результаты. Дополнительные библиотеки не нужны. Команда выдаёт JSON с движком, параметрами, проверками и фактическими значениями; для свидетельства запуска можно сохранить вывод в файл.

На [учебных строках](fixture.sql) за август ожидается 6 попыток, из них 3 успешных: доля 0,5. Сумма длительностей успешных попыток — 97 200 секунд, среднее — 32 400 секунд, то есть 9 часов. Сценарий, начавшийся в конце августа и завершившийся в сентябре, остаётся в августовской группе. Отмена, ошибка и тайм-аут входят в знаменатель доли, но не в среднее время.

Каждый запрос возвращает одну строку на продукт и период, параметры, компоненты формулы, `calculation_status` и значение. Для доли это шкала 0–1; для времени — секунды. `calculated` означает выполнение арифметики на переданной таблице, а не согласование определения или проверку данных. Для пустой группы доля — `NULL` с `empty_cohort`; при отсутствии успехов среднее — `NULL` с `no_successes`. Сбой подключения нельзя заменять пустой группой.

При объединении непересекающихся групп доля пересчитывается из суммарных успехов и попыток, среднее — из суммарных длительностей и успехов. Дополнительного преобразования на графике здесь нет.

## Что проверяется

Сохранённый [результат запуска](verification.json) содержит параметры и фактические значения. Скрипт проверяет арифметику, границы месяца, продуктовый фильтр, завершение в следующем месяце, границу зрелости, предварительный срез, пустую группу и отсутствие успехов. Ограничения учебной таблицы отклоняют повтор сценария, отсутствующую, отрицательную и слишком большую длительность успеха. Это проверка условий входа, а не реализация удаления дублей событий.

Данные организации, подготовка из событий, полнота и доставка не проверены. Свидетельство запуска относится только к этим двум запросам и учебным строкам; оно не повышает статус проверки всей метрики.
