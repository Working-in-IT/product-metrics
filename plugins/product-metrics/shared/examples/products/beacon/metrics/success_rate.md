# Доля успешных сценариев — Beacon

Это учебное определение доли в шкале от 0 до 1; для показа в процентах значение умножается на 100.

## Смысл и применение

Показывает вероятность формального успеха начатой попытки. Помогает оценить надёжность сценария и не принять исключение трудных случаев за ускорение.

## Определение и расчёт

`success_rate = S / A`. Числитель — [успешные сценарии](successful_scenarios.md), знаменатель — [все допустимые начатые сценарии](scenarios.md). Обе метрики версии 1, одной зрелой когорты, одинакового среза и даты получения данных. Единица наблюдения — сценарий. Объединять непересекающиеся группы через `sum(S) / sum(A)`, не среднее их долей.

## Границы

Применяются [учебные правила Beacon](../../../DATA_CONTRACT.md). Отмены, ошибки и тайм-ауты остаются в знаменателе. При `A = 0` результат `null`, причина — отсутствие попыток. При недоступных данных результат тоже неизвестен, но с отдельной причиной. Пропуски, дубли и поздние события обрабатываются одинаково в числителе и знаменателе.

## Источник и проверка

Основание — учебные правила и две карточки компонентов; реального согласования нет. Реальная цепочка расчёта не реализована и имеет состояние `not_checked`. Для последней агрегации есть отдельный учебный SQL.

Сохранённое свидетельство учебного запуска: [параметры и результаты](../../../sql/verification.json).

### Как посчитать

Полный запрос — [success_rate.sql](../../../sql/success_rate.sql), учебная реализация 1 определения `beacon.success_rate`, версия 1; код фиксируется выпуском плагина `v0.2.0`. Движок — SQLite, вход — подготовленная `scenario_facts`, одна строка на сценарий. Удаление дублей событий, определение исхода и исключение дефектных записей выполняются до запроса и здесь не проверены.

Параметры — `product_id`, `period_start` включительно, `period_end` исключительно, `as_of`, время по UTC. Для августа: `beacon`, `2026-08-01T00:00:00Z`, `2026-09-01T00:00:00Z`, `2026-09-04T00:00:00Z`. Передача параметров и требования к источнику — в [инструкции запуска](../../../sql/README.md).

Результат — одна строка на продукт и месяц: попытки, успехи, доля 0–1 и состояние расчёта. На [учебных данных](../../../sql/fixture.sql) ожидается 3 / 6 = 0,5. Арифметика и граничные случаи — `passed` 01.10.2026, свидетельство воспроизводится [проверяющим скриптом](../../../sql/run_examples.py). Это не проверка полноты событий или данных организации; состояние полной реализации остаётся `not_checked`.

## Интерпретация

Рост обычно желателен при сопоставимом составе сценариев. Исключение отмен из знаменателя меняет смысл: это новая версия, после которой нельзя автоматически продолжать прежний ряд.

## Связи и использование

В [системе Beacon](../METRICS_SYSTEM.md) две связи `calculated_from` описывают формулу; другая связь использует эту метрику для защиты интерпретации времени.
