# Диагностика: от «метрика изменилась» к проверяемому объяснению

Маршрут скилла `diagnose-metric`. Уровни вывода - [принципы](PRINCIPLES.md), приём чисел - [рукопожатие с данными](DATA_HANDSHAKE.md), версии - [формат](FORMAT.md). Итог диагностики: ошибка расчёта, локализация, проверяемая гипотеза или план проверок. Единственную причину не обещают.

## 1. Запись о симптоме

- **R-01. Сначала запись, потом расследование.** Когда: любой вопрос «почему изменилась». Проверка: шесть полей заполнены; пробел записан словом «неизвестно» с последствием для вывода. Набор из шести полей - формат плагина, не заимствован из источника; Uber подтверждает лишь «одно имя - одно определение».

| Поле | Что записать |
|---|---|
| Симптом | Метрика, два значения, продукт, процесс |
| Определение | Ключ, версия, формула, единица наблюдения, окно |
| База сравнения | Прошлый период, сезон, план или контроль |
| Состояние данных | Дата получения, зрелость, известные задержки |
| Решение | Что сделают иначе в зависимости от ответа |
| Неизвестности | Что не установлено |

«Почему упал чек» и «отменять ли промо» начинаются с одного числа. Второй вопрос требует маржи, объёма и последствий отмены: решение задаёт глубину работы.

- **R-02. База сравнения названа.** Когда: любое сравнение. Проверка: прошлый период показывает прошлое, план - желаемое, контроль - эффект действия; одно другим не подменяют. Для сезонности берут тот же период прошлого года (Sequoia, часть III); усреднение по 7 дням - выбор плагина. Годового ряда нет - запиши: изменение к выбранной базе измерено, необычность не установлена. Три окна не обязательны - это правило плагина.

## 2. Сопоставимость

- **R-03. Данные раньше причин.** Когда: изменение требует объяснения. Проверка по порядку: события и даты, знаменатели, дубли, фильтры, состав затрат. Симптом начался сразу после правки запроса - сначала реализацию (это эвристика плагина и приоритет проверки, не вывод). Конфликт исходов в событиях расследуют, сценарий молча из N не убирают.
- **R-04. Версии определения и реализации.** Когда: ряд или сравнение. Проверка: версия одна по всему ряду. Изменились популяция или событие успеха - новая версия, ряд пересчитан или показан разрыв; сдвиг методики не складывают с эффектом продукта. Исправлен запрос при прежнем определении - смысл тот же, числа другие: сохрани обе версии и следствие.
- **R-05. Зрелое окно.** Когда: последний период свежий. Проверка: у каждой единицы прошло полное окно наблюдения (учебный Beacon: конец месяца, плюс 24 часа на исход и 48 часов на доставку событий). Иначе жди или сравни одинаково зрелые части; незавершённые из знаменателя не убирай. Зрелость данных - не лаг эффекта.
- **R-06. Дефект расчёта.** Когда: найден дефект. Проверка: исправь, пересчитай, заново подтверди симптом; исправление - самостоятельный итог. Разницу, которую дефект мог породить целиком, причиной не объясняй; на пригодной части данных локализацию продолжают, если ограничение вывод не меняет. Расчёт по присланным цифрам называй «по предоставленным агрегатам».

## 3. Сигнал или шум

- **R-07. Выход за обычную вариацию.** Когда: сопоставимое изменение и есть ряд прошлых значений. Проверка: карта отдельных значений (XmR). Центр - среднее x̄; MR - модуль разности соседних значений, MR̄ - их среднее. Пределы: x̄ ± 2,66·MR̄, то есть x̄ ± 3·MR̄/1,128 (1,128 - константа d2 для пары, 2,66 = 3/1,128 округлённо). Внутри пределов точку не объясняют, наблюдение продолжают; вне - сигнал, его раскладывают. Ряда нет - «необычность не установлена», дальше как при сигнале. Сколько точек нужно, источники не задают: в примере NIST первые 10 партий, Barr советует в идеале 20 и больше; 8 точек - учебный минимум, пределы предварительные. Правило «внутри не объяснять» - вывод плагина.

## 4. Разложение

- **R-08. Вид метрики задаёт разложение.** Когда: перед расчётом. Проверка: сумма - непересекающиеся части; доля - числитель и знаменатель с их популяциями; среднее - веса, состав против внутри групп; воронка - переходы между согласованными шагами.
- **R-09. Сегменты и замыкание.** Когда: среднее или доля по сегментам. Проверка: сегменты не пересекаются и полны (заказ - в одном сегменте, клиент может быть в двух); правила измерения одинаковы в обоих окнах; вес берут из знаменателя метрики (AOV - доля заказов, не выручки; среднее успешных - доля успешных); сумма вкладов равна наблюдаемой разнице. Не сошлось - стоп, до причин.
- **R-10. Порядок факторов.** Когда: два и больше фактора. Проверка: порядок назван или результат усреднён по порядкам. Для «состав, затем ставка»: структура = Σ(w1-w0)·a0, средние = Σw1·(a1-a0). Другой порядок даёт другие слагаемые при той же сумме; для двух факторов среднее двух порядков совпадает с Шепли.
- **R-11. Метод по форме данных.** Когда: выбор глубины. Проверка: два периода и два фактора - R-10; три и больше факторов или несколько измерений - LMDI (без остатка, нулевой срез недопустим); микроданные с ковариатами - Oaxaca-Blinder; автопоиск срезов (Adtributor, RiskLoc, Pinterest) даёт кандидатов, не диагноз. Тяжёлые методы - когда спор «состав или ставка» повторяется и решение дорогое; порог повторений - предложение плагина.
- **R-12. Появился или исчез сегмент.** Когда: сегмента нет в одном окне. Проверка: среднее без заказов не определено - не 0, а `null`; правило сопоставления сегментов раскрыто. До него атрибуция не завершена, допустимы общие отношения сумм. Общее среднее определено при N > 0.
- **R-13. Среднее успешных условно.** Когда: m = T/S. Проверка: неуспешные в m не входят; m оценивают вместе с r, объёмом, сложностью; неопределённое качество названо неизвестным. Сегмент (сложность) определён на старте, не по исходу.
- **R-14. Вклад - не причина и не совет.** Когда: любое слагаемое. Проверка: рядом порядок и слова «причина не установлена». Не переводи: разницу выручки - в потерянную прибыль; календарные минуты - в экономию труда; контрфактическое значение (старые средние при новом составе) - в результат политики; размер процента - в значимость или деньги. Из формулы не следует «уменьши число заказов».

## 5. Локализация и механизм

- **R-15. Срез отвечает «где».** Когда: локализация. Проверка: срез выбран, потому что различает две названные версии; стабильный сегмент - не контрольная группа. Первой идёт дешёвая проверка: не менялось ли определение сегмента и классификатор. Затем механизмы: изменения продукта (время сдвига против времени выката), сезонность, внешние события и конкуренты, смена состава.
- **R-16. Парные метрики и время.** Когда: после локализации. Проверка: рядом смотрят парную метрику (чек - конверсия и маржа; скорость - успех); дата сдвига согласована с порядком событий и лагом. Совпадение дат - свидетельство для проверки, не доказательство.

## 6. Степень знания и остановка

- **R-17. Слово уровня и право остановиться.** Когда: перед выводом. Проверка: в тексте уровень шкалы из [принципов](PRINCIPLES.md) (раздел 4); разложение даёт «локализовано». Шкала уровней и слово «локализовано» - соглашение плагина, не заимствованы из источника. У каждой гипотезы есть проверка и то, что её опровергнет. «Причина не установлена» - не «причины нет»: записаны результат, ограничение, условие возврата. План проверок - допустимый итог.

## 7. Записка

- **R-18. Фиксированный шаблон, до 350 слов.** Когда: итог любой диагностики. Проверка: восемь полей, пустое названо; вывод не сильнее слабейшей строки блока данных. Восемь полей и предел 350 слов (без блока данных и таблиц) - собственный формат плагина, не взятый из источника; Sequoia, часть VII, подтверждает лишь, что анализ завершается планом действий.

```
Данные: <блок по рукопожатию, до 6 строк>
1. Вопрос
2. Определение и база
3. Наблюдения (значения, окна, необычность)
4. Локализация и вклад (порядок; сумма = разница; причина не установлена)
5. Открытые гипотезы: версия | как проверить | что опровергнет
6. Действие
7. Условия пересмотра
8. Источники данных
```

С каталогом записку сохраняют в `metrics/memos/<YYYY-MM-DD>-<metric>.md`. Без каталога возвращают в ответе и добавляют одну строку с предложением сохранить.

## 8. Пример: AOV

Окна по 1000 заказов. Premium 700 × 85 -> 550 × 86; Standard 300 × 28 -> 450 × 32. AOV 67,9 -> 61,7.

| Шаг | Результат |
|---|---|
| Ряд (R-07) | 8 недель, последняя - окно A: x̄ = 67,975; MR̄ = 5,3/7 ≈ 0,757; пределы 65,96 ... 69,99. B = 61,7 ниже - сигнал |
| Состав первым (R-10) | Структура -8,55; средние +2,35; сумма -6,2 |
| Средние первыми | Структура -8,10; средние +1,90; среднее двух порядков -8,325 и +2,125 |
| Вывод (R-14, R-17) | Локализовано: чек вырос в обоих сегментах, вырос вес Standard. Причина состава неизвестна |

Заказы одинаковы, разница выручки -6 200 - не потерянная прибыль.
